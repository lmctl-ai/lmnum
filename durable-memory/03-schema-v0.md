# Schema v0 (`schema/lmnum.dsl.json`)

Generated by `scripts/gen-schema.py` from the `method(r, "Type", "name", {params}, "ret", ...)`
registrations in `cpp/main.cpp` (so schema and host cannot drift); `test.sh` also diffs the
registry against `lmscript --dsl-signatures`. One context, `num: Num`; types `Matrix`, `Func`,
`Ode`, `System`; no free functions. 63 methods.

## Objects and ownership

Host objects live in arenas until the process exits (limit 4,000,000 per kind). There is no
`free`; loops that create many large matrices should reuse them (`set`) or keep sizes modest.
Methods named like builders (`Matrix.set`, `Ode.rhs/init/param/tol/stiff`, `System.eq`) return the
receiver so calls chain: `num.ode(2).stiff()` and `sys.init(0, 1.0).init(1, 2.0)`.

## Conventions

- Matrices are dense `double`, 0-based `get(i, j)`. Vectors are n x 1 matrices (`linspace`,
  `eig_sym`, `System.solve`, ...). `col`, `row`, `hstack`, `vstack` build and slice.
- `Num.parse("1 2; 3 4")`: rows separated by `;` or newline, entries by space or comma.
  `Num.load_csv` accepts whitespace or comma separated numbers and skips one alphabetic header row.
  `save_csv` writes space separated `%.10g` values, one row per line.
- `random` and `normal` take an integer seed (mt19937-64), so runs are reproducible; results can
  differ between standard libraries for `normal` (the distribution algorithm is
  implementation-defined), uniform draws are portable.
- Errors (bad index, shape mismatch, singular matrix, parse error, solver failure) throw a host
  error: JSON `{"ok": false, "phase": "run", ...}`, exit code 3.
- `assert_close(a, b, tol)` fails when `|a-b| > tol` (NaN fails).

## ODE and nonlinear systems

`Ode` equations are expressions in `t`, `y0..y{n-1}` and the named parameters. `solve(t0, t1,
points)` returns `points` rows (>= 2), equally spaced, columns `t, y0, ..., y{n-1}`. Default is
CVODE's Adams-Moulton method with a dense linear solver; `stiff()` selects BDF. Tolerances default to rtol 1e-8, atol 1e-10 (`tol(rtol, atol)`).
At most 500,000 internal steps between outputs (error mentions `stiff()` when exceeded).
`System` equations are expressions in `x0..x{n-1}`; `solve(guess, tol)` uses KINSOL with line
search and a dense finite-difference Jacobian.

## Why strings, not callbacks

The DSL compiler checks each `_dsl_` block against the schema and has no function values. An
expression string is also data a script can build (`"k*" + name`), print and log.
